## 1. Перед началом

### Что понадобится

- ЭЛТ-монитор и название его модели (написано на задней стенке). Паспорт пригодится, но он
  не обязателен.
- Способ подключения:

  | Подключение | Что важно |
  |---|---|
  | **Переходник DP→VGA** | Лучший вариант для современной видеокарты. Хорошие переходники дают 200–360 МГц частоты пикселей, дешёвые — 160–180 МГц. crtctl сам читает предел переходника из его регистров. |
  | **Переходник HDMI→VGA** | Обычно не больше 165 МГц (одноканальный HDMI). Хватит на 1024×768@100 или 1280×1024@75. |
  | **DVI-I или родной VGA** | Старые видеокарты; собственный ЦАП карты, обычно 400 МГц. Ограничивает только монитор. |
  | **Конвертер HDMI→AV (тюльпаны, SCART)** | Это для телевизоров, а не для ЭЛТ-мониторов. crtctl его узнаёт и не трогает. |

- Linux с ядром не старше нескольких лет и права `sudo` для постоянной настройки.

### Три числа, которые нужно знать

- **Строчная частота (кГц):** сколько строк в секунду рисует монитор. Это главный предел ЭЛТ:
  21-дюймовый обычно держит 30–95 кГц, 17-дюймовый — 30–70 кГц.
- **Кадровая частота (Гц):** сколько кадров в секунду. Ниже 60 Гц ЭЛТ заметно мерцает,
  85 Гц комфортно, многие мониторы умеют 120–160 Гц.
- **Частота пикселей (МГц):** сколько точек в секунду. Её ограничивает **переходник**.

Режим подходит, когда подходят все три. Чем больше строк (выше разрешение), тем ниже кадровая
частота при той же строчной. Поэтому один и тот же монитор тянет 800×600@140, но
1600×1200 только на 66 Гц.

**Выход** (коннектор) — это разъём видеокарты: `DP-2`, `HDMI-A-1`, `VGA-1`. Все выходы
показывает `crtctl info`.

## 2. Установка crtctl

Проще всего взять готовый файл со страницы
[Releases](https://github.com/ImmortallKIng/crtctl/releases/latest):

```bash
curl -fLo crtctl https://github.com/ImmortallKIng/crtctl/releases/latest/download/crtctl-linux-amd64
sudo install -m755 crtctl /usr/local/bin/crtctl
crtctl --version
```

Это один статический файл без зависимостей, он запускается на любом дистрибутиве. Для плат
на ARM бери `crtctl-linux-arm64`.

Чтобы собрать из исходников, нужен Go 1.22 или новее (пакет `golang`):

```bash
git clone https://github.com/ImmortallKIng/crtctl
cd crtctl
make
sudo make install
```

Если в системе есть `kscreen-doctor` (KDE), `xrandr` (X11), `swaymsg`, `hyprctl` или
`edid-decode`, crtctl ими пользуется. Ставить специально ничего не нужно: если чего-то не
хватит, crtctl скажет.

**Язык.** Интерфейс следует языку системы (английский, русский, испанский, немецкий,
французский). Сменить: `crtctl --lang en info` или `export CRTCTL_LANG=ru`.

## 3. Первая настройка: `crtctl setup`

Подключи монитор и включи его. Сначала посмотри, что crtctl собирается сделать, ничего не
меняя:

```bash
crtctl setup --dry-run
```

Если всё выглядит правильно, запускай по-настоящему:

```bash
crtctl setup
```

`sudo` писать не нужно: crtctl сам попросит пароль, когда понадобится. Перед каждым шагом
он спрашивает, а Enter выбирает предложенный ответ (он заглавный: `[Д/н]`).

### Шаг 1: поиск монитора

```text
1. Ищу CRT-монитор...
   Выход: DP-2 (amdgpu)
   Монитор: HP Ergo 1600 (D2845A), 21" (HWP 2845)
   Переходник: DP 1.1 → VGA, линий 2 × HBR 2.7 Гбит/с, с downspread, без ID производителя; предел около 179.1 МГц
```

crtctl просматривает все подключённые выходы и берёт тот, где аналоговый монитор или
переходник на VGA. Если таких несколько, спросит, какой. Выбрать самому:
`crtctl setup DP-2`.

У переходника DisplayPort crtctl читает регистры (DPCD) и вычисляет пропускную способность.
Для HDMI→VGA принимает 165 МГц.

### Шаг 2: пределы

```text
2. Вычисляю безопасные пределы...
   ✓ Профиль hp-ergo-1600 (найден по EDID)
   Пределы: строчная 30–93.75 кГц, кадровая 50–140 Гц, частота пикселей до 179.1 МГц
```

Пределы берутся по порядку:

1. из профиля, указанного через `--profile ID`;
2. из профиля, подходящего к EDID монитора (встроенного или твоего, см.
   [раздел 6](#6-профили-мониторов));
3. из диапазонов частот, которые монитор сообщает о себе сам;
4. из списка режимов в EDID монитора (это всегда безопасно, но обычно скромно).

Если монитора нет в списке, crtctl **создаст для него профиль** по тому, что сообщает
монитор, и напишет имя файла. Если у тебя есть паспорт, пределы в этом файле можно поднять
и запустить `setup` ещё раз.

Если монитор ничего не сообщает (совсем старые модели или переходники, которые не
пропускают DDC), crtctl попросит выбрать типичный профиль («17 дюймов, 30–70 кГц») или ввести
максимальную строчную частоту из паспорта.

### Шаг 3: режимы

```text
3. Подбираю режимы...
 ! 1280x1024     85.02 Гц   91.15 кГц  157.50 МГц  DTD DMT 0x25   ✓
   640x480      139.53 Гц   73.11 кГц   62.00 МГц  DTD CVT        ✓
   800x600      139.84 Гц   91.45 кГц   99.50 МГц  DTD CVT        ✓
   1024x768     113.91 Гц   93.75 кГц  130.50 МГц  DTD CVT        ✓
   ...
   1600x1200     65.89 Гц   82.29 кГц  177.75 МГц  DTD CVT        ✓
Использовать эти режимы? [Д/н]
```

Для каждого стандартного разрешения crtctl берёт самую высокую подходящую частоту и
добавляет обычные режимы VESA на 60, 75 и 85 Гц. Режим со знаком `!` станет основным: самый
крупный режим от 85 Гц из заявленных самим монитором, а если таких нет — самое крупное
разрешение, которое держит 85 Гц с запасом. Частоты ниже 60 Гц не предлагаются.

Если нужны другие режимы, ответь `н` и смотри [раздел 7](#7-ручное-управление-edid-по-шагам).

### Шаг 4: канал DisplayPort (только переходники DP)

```text
4. Канал DisplayPort
   Многие переходники DP→VGA гаснут на низких разрешениях, потому что драйвер понижает скорость канала. Если держать канал на максимуме переходника, этого не происходит, и это безвредно.
Держать канал DP на максимуме? [Д/н]
```

Соглашайся. Это безвредно и убирает самую частую причину чёрного экрана с дешёвыми
переходниками. Подробнее — в [разделе 9](#9-переходник-dpvga-гаснет-фиксация-канала).

### Шаг 5: проверка

```text
5. Проверка перед установкой...
   ✓ Новые режимы действуют до перезагрузки (повторное определение amdgpu (trigger_hotplug=1)).
   Открой настройки экрана и попробуй несколько режимов или в другом терминале: crtctl try DP-2 1024x768@85
Всё выглядит нормально? Установить навсегда? [д/Н, 60 с]
```

Новые режимы уже загружены, но только до перезагрузки. Открой настройки экрана, выбери
несколько режимов и посмотри на картинку. Потом вернись в терминал и напиши `д`.

**Если экран погас или монитор пишет «out of range», просто подожди.** Если в течение 60
секунд не ответить «да», crtctl вернёт прежний EDID и ничего не установит.

### Шаг 6: постоянная установка

crtctl кладёт файл EDID туда, где его найдёт ядро при загрузке, добавляет его в initramfs и
прописывает параметр ядра `drm.edid_firmware=`. Генератор initramfs и загрузчик он
определяет сам (см. [что где работает](#11-что-где-работает)).

```text
✓ Готово: DP-2 настроен. Режимы сохранятся после перезагрузки.
  Поэкспериментировать с любым режимом: crtctl try DP-2 1000x500@75
  Проверить потом: crtctl doctor
  Откатить: sudo crtctl remove DP-2
```

Перезагрузись один раз и убедись, что режимы на месте, а потом выбери нужный в настройках
экрана.

### Полезные параметры

| Параметр | Что делает |
|---|---|
| `--dry-run` | только показать, что будет сделано |
| `--yes` | на все вопросы ответ по умолчанию; проверка всё равно ждёт твоего «да» (для полностью автоматического запуска добавь `--no-test`) |
| `--no-test` | пропустить проверку (если ты уже знаешь, что режимы работают) |
| `--profile ID` | взять этот профиль монитора |
| `--hmax 85 --vmax 120` | задать пределы вручную |
| `--pclk 200` | задать предел переходника вручную |
| `--method service` | ставить через сервис systemd, а не через параметр ядра |
| `--current-kernel` | пересобрать initramfs только для текущего ядра (быстрее) |

## 4. Эксперименты: `crtctl try`

`try` сразу показывает любой режим и ничего не устанавливает:

```bash
crtctl try 1000x500@75
crtctl try DP-2 640x480@120
crtctl try DP-2 1280x960@85 --seconds 30
```

```text
Пробую 1000x500      74.68 Гц   39.21 кГц   50.50 МГц (2:1), CVT
Переключаю через KDE (kscreen-doctor)...
✓ Монитор сейчас получает: 1000x500      74.68 Гц   39.21 кГц   50.50 МГц  CVT
Нажми Enter в течение 15 с, чтобы оставить; иначе вернётся прежний режим.
```

- Сначала режим проверяется по пределам. Если он не подходит, crtctl откажется и объяснит
  почему. `--force` отключает проверку; пользуйся им, только если точно знаешь, что монитор
  это выдержит.
- После переключения crtctl считывает режим у ядра, так что ты видишь, что монитор получает
  на самом деле.
- **Если не нажать Enter, через 15 секунд вернётся прежний режим** (или через
  `--seconds N`). Чёрный экран исправится сам.
- Оставленный режим действует, пока ты его не сменишь или не выйдешь из сеанса. Чтобы
  оставить его навсегда, добавь его в EDID: `crtctl edid build DP-2 1000x500@75 --best`, потом
  `sudo crtctl apply` (см. раздел 7).

### Точные тайминги

По умолчанию для стандартных режимов берутся тайминги VESA DMT, для остальных — CVT.
Можно выбрать самому:

```bash
crtctl try 1024x768@100 --kind gtf
crtctl try --modeline "157.5 1280 1344 1504 1728 1024 1025 1028 1072 +hsync +vsync"
```

Modeline записывается так же, как в `xrandr` и старых `xorg.conf`: частота пикселей в МГц,
четыре числа по горизонтали, четыре по вертикали, полярность синхроимпульсов.

### Рабочие столы

| Рабочий стол | Как `try` переключает | Примечание |
|---|---|---|
| KDE Plasma (Wayland) | `kscreen-doctor` | KDE строит режимы только по CVT. Если просишь DMT или GTF, crtctl об этом скажет. |
| Любой на X11 | `xrandr` | точные тайминги |
| Sway | `swaymsg` | точные тайминги |
| Hyprland | `hyprctl` | точные тайминги |
| GNOME на Wayland и остальные | временный EDID | `sudo crtctl try DP-2 1000x500@75 --via edid` |

В GNOME нельзя добавить режим снаружи, поэтому crtctl загружает временный EDID с нужным
режимом. Режим появляется в «Параметры → Дисплеи», выбери его там. Когда насмотришься,
нажми Enter в терминале, и прежний EDID вернётся. Для этого нужны `sudo` и открытый debugfs
(см. [Secure Boot](#secure-boot-и-kernel-lockdown)).

Во всех остальных случаях запускай `try` **без** `sudo`: ему нужно общаться с твоим
рабочим столом.

## 5. Что возможно: `modes` и `calc`

`modes` отвечает на вопрос «насколько высоко можно подняться в каждом разрешении»:

```text
$ crtctl modes DP-2
РАЗРЕШЕНИЕ  МАКС ГЦ  КГЦ    МГЦ     ТИП  УПИРАЕТСЯ В        ЗАМЕТКИ
640x480     139.53   73.11  62.00   CVT  кадровая монитора
1024x768    113.91   93.75  130.50  CVT  строчная монитора
1280x1024   86.89    93.75  163.50  CVT  строчная монитора
1600x1200   65.89    82.29  177.75  CVT  переходник
1792x1344   52.93    73.47  177.50  CVT  переходник         ниже 60 Гц: заметное мерцание
1856x1392   —                                               не проходит ни на одной частоте
```

Колонка **УПИРАЕТСЯ В** подсказывает, что менять:

- `кадровая монитора` / `строчная монитора`: предел — сам монитор, выше не прыгнуть.
- `переходник`: с более быстрым переходником будет больше. В примере переходник на 180 МГц
  держит 1600×1200 на 66 Гц, а с переходником на 230 МГц было бы 85 Гц.

Параметры: `--wide` добавляет широкоформатные разрешения, `--kind gtf` меняет формулу,
`--kernel` проверяет все режимы, которые ядро предлагает прямо сейчас.

`calc` показывает точные тайминги одного режима и проверяет его:

```text
$ crtctl calc DP-2 1000x500@75 --all
1000x500      74.68 Гц   39.21 кГц   50.50 МГц  [CVT]
  Modeline "1000x500_74.68" 50.50 1000 1048 1144 1288 500 503 513 525 -hsync +vsync
  ✓ в пределах
1000x500      74.75 Гц   38.79 кГц   45.00 МГц  [CVT-RB]
  ⚠ reduced blanking рассчитан на ЖК; CRT может не успевать с обратным ходом луча
```

Без имени выхода `calc` просто считает, без проверок.

## 6. Профили мониторов

Профиль — это диапазоны частот монитора из паспорта. Несколько профилей встроено:

```text
$ crtctl profiles
ID                МОНИТОР                                КГЦ       ГЦ
generic-crt-15in  Типичный CRT 15 дюймов (30–54 кГц)     30–54     50–120
generic-crt-17in  Типичный CRT 17 дюймов (30–70 кГц)     30–70     50–160
generic-crt-19in  Типичный CRT 19 дюймов (30–96 кГц)     30–96     50–160
generic-crt-21in  Типичный CRT 21 дюйм (30–110 кГц)      30–110    50–160
...
hp-ergo-1600      HP Ergo 1600 (D2845A), 21"             30–93.75  50–140
```

Свой профиль нужен, когда EDID монитора занижает его возможности или когда EDID нет вовсе.
Создай заготовку:

```bash
crtctl profiles --new my-crt
```

Появится файл `~/.config/crtctl/monitors/my-crt.json`. Заполни его по паспорту:

```json
{
  "id": "my-crt",
  "name": "Мой 19-дюймовый CRT",
  "match": ["ABC 1234"],
  "hmin_khz": 30,
  "hmax_khz": 96,
  "vmin_hz": 50,
  "vmax_hz": 160,
  "max_res": "1600x1200@75",
  "notes": "Значения из паспорта"
}
```

| Поле | Что значит |
|---|---|
| `hmin_khz`, `hmax_khz` | диапазон строчной частоты из паспорта |
| `vmin_hz`, `vmax_hz` | диапазон кадровой частоты |
| `match` | код производителя и модели: первые два слова строки `Монитор:` в `crtctl info` (например, `HWP 2845`). С ним crtctl подхватит профиль сам. Если у монитора нет EDID, убери поле и указывай `--profile my-crt`. |
| `bandwidth_mhz` | необязательно: полоса видеоусилителя. Выше неё картинка мылится, но ничего не ломается, поэтому это не жёсткий предел. |
| `max_res`, `notes` | для тебя; их показывает `crtctl profiles my-crt` |

Твои профили заменяют встроенные с тем же `id`. Профили, созданные мастером `setup`, лежат в
`/etc/crtctl/monitors/`.

**Бери цифры из паспорта, а не наугад.** Превышение строчной частоты может повредить старый
монитор без защиты.

Если твоего монитора нет в списке, а паспорт есть, пришли профиль через pull request.

## 7. Ручное управление: EDID по шагам

`setup` делает всё это сам. Отдельные команды нужны, если хочешь собрать свой набор режимов.

**Немного теории.** EDID — небольшой блок данных, в котором монитор описывает себя и
перечисляет свои режимы. Через переходник система часто получает плохой EDID или вообще
никакого. crtctl собирает новый и заставляет ядро использовать его вместо настоящего.

```bash
# 1. Прочитать настоящий EDID монитора (для копии или чтобы посмотреть)
crtctl edid read DP-2                     # → edid-DP-2.bin

# 2. Разобрать EDID: файл или тот, что ядро использует для выхода
crtctl edid show DP-2
crtctl edid show edid-DP-2.bin

# 3. Собрать свой. Первый режим станет основным.
crtctl edid build DP-2 1280x1024@85 1000x500@75 --best    # → crtctl-DP-2.bin

# 4. Загрузить до перезагрузки и посмотреть режимы
sudo crtctl apply DP-2 crtctl-DP-2.bin --test

# 5. Установить навсегда
sudo crtctl apply DP-2 crtctl-DP-2.bin
```

`edid build` копирует производителя, модель и серийный номер из настоящего EDID монитора,
поэтому рабочий стол продолжает его узнавать и помнит его настройки. Каждый режим
проверяется по пределам (`--force` собирает всё равно). В EDID помещается до 20 своих
режимов плюс стандартные режимы VESA.

| Параметр `edid build` | Что делает |
|---|---|
| `--best` | добавить лучшую частоту для каждого разрешения 4:3 и 5:4 |
| `--kind cvt\|gtf` | формула для нестандартных режимов |
| `--name "My CRT"` | имя монитора, до 13 латинских символов |
| `--base ФАЙЛ` | взять данные монитора из этого файла EDID, а не с монитора |
| `--no-range` | не записывать диапазоны частот |
| `-o ФАЙЛ` | имя выходного файла |

`apply` проверяет, что EDID собран для подключённого сейчас монитора, и иначе отказывается
(`--force` ставит всё равно).

**`reprobe`** заставляет драйвер перечитать EDID, как будто кабель перевоткнули:
`sudo crtctl reprobe DP-2`. С `--hard` разрешено программное переподключение (экран моргнёт).

## 8. Свои режимы в KDE Plasma

KDE Plasma 6.6 и новее умеет сама добавлять режимы, без EDID и без root. Они сохраняются,
пока ты их не удалишь.

```bash
crtctl kde list DP-2              # какие режимы есть в KDE, с проверкой по пределам
crtctl kde add DP-2 1152x864@100  # добавить режим
crtctl kde best DP-2              # добавить лучшую частоту для каждого разрешения 4:3/5:4
crtctl kde set DP-2 1152x864@100  # переключиться (без Enter вернётся прежний)
crtctl kde remove DP-2 61 62      # удалить режимы по номерам из «kde list»
crtctl kde remove DP-2 all
```

KDE считает такие режимы по CVT. Для точных таймингов VESA используй EDID.

## 9. Переходник DP→VGA гаснет: фиксация канала

**Признак:** высокие разрешения работают, а на 640×480 или 800×600 экран чёрный, или
картинка пропадает после выхода монитора из сна.

**Причина:** на лёгких режимах драйвер экономит энергию и замедляет канал DisplayPort
(меньше линий, ниже скорость). Многие дешёвые переходники за этим не успевают.

**Решение** (только amdgpu):

```bash
sudo crtctl link show DP-2                  # что умеет переходник и что включено сейчас
sudo crtctl link force DP-2 --persistent    # держать максимум, в том числе после загрузки
sudo crtctl link remove DP-2                # отменить
```

`--lanes 2 --rate hbr` задаёт конфигурацию вручную. `--persistent` ставит сервис systemd
`crtctl-link-DP-2.service`. `setup` предлагает этот шаг сам.

## 10. Особые случаи

### NVIDIA

- Драйвер должен работать с kernel modesetting: параметр ядра `nvidia-drm.modeset=1`. В
  свежих драйверах он включён по умолчанию. `crtctl doctor` это проверяет.
- NVIDIA не связывает выходы с их шиной DDC в системе, поэтому crtctl ищет шину сам.
- **X11:** X-драйвер NVIDIA сам читает EDID и не видит подмену в ядре. Поэтому `apply` и
  `setup` дополнительно пишут `/etc/X11/xorg.conf.d/90-crtctl-nvidia.conf` с параметром
  `CustomEDID`. После этого выйди из сеанса и зайди снова. Если секция `Device` для NVIDIA уже
  есть в твоём конфиге, crtctl её не трогает и печатает строки, которые туда добавить.
- **Wayland:** работает как с другими драйверами.
- В драйвере 580.105.08 есть ошибка: он игнорирует свои EDID. Обнови до 580.119.02 или
  новее. `doctor` об этом предупредит.
- Фиксация канала DP недоступна.

### Intel

i915 и xe работают как amdgpu, кроме фиксации канала DP.

### Secure Boot и kernel lockdown

С Secure Boot ядро обычно работает в режиме **lockdown** и закрывает debugfs. Тогда:

- **постоянная установка работает** (она идёт через параметр ядра);
- проверка в `setup`, `apply --test`, `try --via edid`, `reprobe` и `link` не работают.
  `setup` об этом скажет, и режимы появятся после перезагрузки.

Включён ли lockdown, показывает `crtctl doctor`.

### Неизменяемые системы: Silverblue, Kinoite, Bazzite

Там `/usr` только для чтения, поэтому EDID кладётся в `/etc/crtctl/firmware`, а crtctl
пользуется `rpm-ostree initramfs-etc` и `rpm-ostree kargs`. Нужна перезагрузка, как после
любого изменения rpm-ostree.

### NixOS

crtctl не меняет настройки загрузки NixOS. Он печатает строки для `configuration.nix`, после
чего нужно выполнить `nixos-rebuild switch`.

### Нет systemd или загрузчик не распознан

Если crtctl не узнал загрузчик, он ставит сервис systemd, который подкладывает EDID при
загрузке (`--method service`; нужен debugfs). Без systemd (Void, Artix, Alpine) он печатает
шаги для ручной настройки.

## 11. Что где работает

**Дистрибутивы**

| Дистрибутив | initramfs | параметры ядра |
|---|---|---|
| Fedora, RHEL, Alma, Rocky | dracut | grubby |
| Fedora Silverblue / Kinoite, Bazzite | rpm-ostree initramfs-etc | rpm-ostree kargs |
| Ubuntu, Debian, Mint, Zorin, elementary | initramfs-tools | файл GRUB `/etc/default/grub.d/99-crtctl.cfg` |
| Pop!_OS | initramfs-tools | kernelstub |
| Arch, Manjaro, EndeavourOS, CachyOS | mkinitcpio или dracut | GRUB или systemd-boot |
| openSUSE | dracut | GRUB 2 |
| любой другой с systemd | — | сервис при загрузке (`--method service`) |
| NixOS | — | печатаются строки для `configuration.nix` |

**Видеодрайверы**

| Драйвер | Подмена EDID | Мгновенная проверка (debugfs) | Фиксация канала DP |
|---|---|---|---|
| amdgpu | ✓ | ✓ | ✓ |
| i915 / xe (Intel), nouveau, radeon | ✓ | ✓ | — |
| NVIDIA (проприетарный и open) | ✓ при `nvidia-drm.modeset=1`; на X11 ещё и `CustomEDID` | ✓ на Wayland | — |

**Переходники: как определяется предел частоты пикселей**

| Подключение | Как определяется | Предел |
|---|---|---|
| DP→VGA с доступными регистрами | регистры DisplayPort (DPCD) | предел ЦАП переходника, если он его сообщает, иначе пропускная способность канала минус 0.5% на downspread |
| DP→VGA без данных (например, NVIDIA) | аналоговый EDID на выходе DP | 165 МГц для осторожности; меняется через `--pclk` |
| HDMI→VGA, DVI-D→VGA | аналоговый EDID на цифровом выходе | 165 МГц |
| родной VGA, DVI-I | тип выхода | ЦАП видеокарты, обычно 400 МГц |
| конвертер HDMI→AV (телевизор) | цифровой EDID | это не вход ЭЛТ, пределы не применяются |

## 12. Решение проблем

Начни с этого:

```bash
crtctl doctor          # без root
sudo crtctl doctor     # ещё проверит переходник и debugfs
```

Команда перечислит проблемы и для каждой покажет команду, которая её исправит.

**Монитор пишет «out of range» или «frequency over».** Режим выше, чем монитор умеет. Если это
случилось в `try` или во время проверки в `setup`, подожди: всё вернётся само. Если так
происходит с установленным EDID, в профиле завышены пределы: уменьши `hmax_khz` в профиле и
запусти `setup` ещё раз.

**Экран чёрный только на низких разрешениях.** Это переходник DP, см.
[раздел 9](#9-переходник-dpvga-гаснет-фиксация-канала).

**После `setup` новых режимов нет.** Перезагрузись. Если их всё ещё нет, запусти
`crtctl doctor`: он покажет, загрузило ли ядро EDID, и если нет, то почему.

**Только 60 Гц и пара разрешений.** Переходник не пропускает EDID монитора, или EDID
скудный. Запусти `crtctl setup`, он спросит профиль.

**`try` пишет, что KDE строит режимы только по CVT.** Это ограничение KDE. Режим CVT почти
такой же; для точных таймингов DMT используй `sudo crtctl try ... --via edid`.

**«укажи коннектор, подключено несколько».** crtctl не смог понять,
какой монитор ты имеешь в виду (ни один или несколько похожи на ЭЛТ). Добавь имя выхода:
`crtctl try DP-2 800x600@120`.

**На высоких разрешениях картинка мыльная.** Это полоса видеотракта монитора или ЦАП
переходника. Возьми разрешение или частоту чуть ниже.

**Поменял монитор на том же разъёме.** Установленный EDID привязан к разъёму. `doctor`
предупредит, что подключён другой монитор. Запусти `crtctl setup` ещё раз или
`sudo crtctl remove DP-2`.

**Картинка сдвинута или не того размера.** Для нового режима на ЭЛТ это нормально. Подстрой
её кнопками монитора; большинство мониторов запоминают настройку для каждого режима.

**Сообщить об ошибке.** [Открой issue](https://github.com/ImmortallKIng/crtctl/issues/new/choose)
и приложи вывод `crtctl doctor`, `sudo crtctl doctor` и `crtctl info`.

## 13. Чёрный экран после перезагрузки: как вернуть

Такого быть не должно, потому что `setup` ставит только режимы, которые ты подтвердил. Но
если после перезагрузки экран чёрный:

1. **Используй другой выход, если он есть.** Подмена EDID действует только на разъём ЭЛТ,
   так что другой монитор или телевизор работают как обычно. Зайди через него и выполни
   `sudo crtctl remove DP-2`.
2. **Убери параметр ядра на одну загрузку.** В меню загрузки (GRUB: клавиша `e`;
   systemd-boot: тоже `e`) найди в строке ядра `drm.edid_firmware=...`, удали его и загрузись
   (в GRUB: Ctrl+X). Система стартует с родным EDID монитора. Затем выполни
   `sudo crtctl remove DP-2`.
3. **Способ service:** так же добавь в строку ядра `systemd.mask=crtctl-edid.service`.
4. **По сети:** если включён SSH, зайди с другого компьютера, выполни
   `sudo crtctl remove DP-2` и перезагрузись.

Перед первой правкой crtctl сохраняет `/etc/default/grub` и записи загрузчика с
суффиксом `.crtctl-backup`.

## 14. Откатить всё

```bash
sudo crtctl remove DP-2          # всё для этого выхода
sudo crtctl remove DP-2 --edid   # только EDID
sudo crtctl remove DP-2 --link   # только фиксацию канала DP
```

Картинка не изменится до следующей перезагрузки. Созданные профили остаются; если они не
нужны, удали их из `~/.config/crtctl/monitors/` и `/etc/crtctl/monitors/`.

Удалить саму утилиту: `sudo rm /usr/local/bin/crtctl` (или `sudo make uninstall`), а после
`remove` ещё `sudo rm -r /etc/crtctl`.

## 15. Что crtctl меняет в системе

| Файл | Зачем |
|---|---|
| `/usr/lib/firmware/edid/crtctl-ВЫХОД.bin` | EDID (на неизменяемых системах — `/etc/crtctl/firmware`) |
| `/etc/dracut.conf.d/crtctl-edid.conf`, `/etc/mkinitcpio.conf.d/crtctl-edid.conf`, `/etc/initramfs-tools/hooks/crtctl-edid` | добавляют EDID в initramfs |
| параметр ядра `drm.edid_firmware=ВЫХОД:edid/crtctl-ВЫХОД.bin` | говорит ядру, какой EDID брать для какого выхода |
| `/etc/default/grub.d/99-crtctl.cfg` или `/etc/default/grub`, записи загрузчика | куда пишется параметр ядра; перед первой правкой сохраняется копия `.crtctl-backup` |
| `/etc/systemd/system/crtctl-edid.service`, `/etc/crtctl/apply-edid.sh` | установка способом service |
| `/etc/systemd/system/crtctl-link-ВЫХОД.service` | фиксация канала DP при загрузке |
| `/etc/X11/xorg.conf.d/90-crtctl-nvidia.conf` | только NVIDIA на X11 |
| `/etc/crtctl/state.json` | что установлено, регистры переходника |
| `/etc/crtctl/monitors/`, `~/.config/crtctl/monitors/` | профили мониторов |

Больше ничего не трогается. `crtctl remove` откатывает всё это для выхода.

## Словарик

| Термин | Что значит |
|---|---|
| **EDID** | данные, которые монитор сообщает о себе: имя, размер, режимы, диапазоны частот |
| **DDC** | линия (I²C), по которой читается EDID |
| **DPCD** | регистры устройства DisplayPort; из них crtctl узнаёт пределы переходника |
| **DMT** | таблица стандартных режимов VESA с точными таймингами (1024×768@85 и т. п.) |
| **CVT, GTF** | формулы VESA, которые рассчитывают тайминги для любого разрешения и частоты |
| **CVT-RB** | CVT с сокращённым гашением; рассчитан на ЖК, для ЭЛТ часто слишком короткий |
| **Modeline** | режим, записанный числами: частота пикселей и тайминги по горизонтали и вертикали |
| **Частота пикселей** | точек в секунду, в МГц; предел переходника |
| **Строчная частота** | строк в секунду, в кГц; главный предел ЭЛТ |
| **Downspread** | небольшое «размазывание» частоты канала DP против помех; съедает 0.5% пропускной способности |
| **debugfs** | интерфейс ядра, через который crtctl подгружает EDID без перезагрузки |
| **initramfs** | маленькая файловая система, с которой стартует ядро; EDID должен быть в ней, чтобы работать с самого начала |
| **KMS** | kernel mode setting: видеорежим ставит ядро, а не X-сервер |
