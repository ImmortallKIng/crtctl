**ЭЛТ-мониторы на современном Linux без мучений.** Утилита делает то же, что CRU (Custom
Resolution Utility) на Windows, а вдобавок сама определяет монитор и переходник, проверяет
каждый режим на безопасность и одной командой показывает любое разрешение.

## Зачем

У современных видеокарт нет аналогового выхода, поэтому ЭЛТ подключают через переходник
DP→VGA или HDMI→VGA. Переходник прячет монитор от системы, и в итоге доступны 60 Гц, пара
разрешений, а иногда вообще чёрный экран. Чтобы вернуть 85–140 Гц, обычно приходится вручную
собирать EDID, прописывать параметры ядра и хуки initramfs, причём в каждом дистрибутиве
по-своему.

`crtctl` делает это за тебя:

- **Воткнул и запустил `crtctl setup`.** Утилита находит ЭЛТ, распознаёт переходник и его
  пропускную способность, вычисляет безопасные пределы, собирает EDID с лучшими режимами,
  даёт их проверить и ставит так, чтобы всё пережило перезагрузку.
- **Пробуй что угодно.** `crtctl try DP-2 1000x500@75` сразу показывает любой режим и сам
  возвращает прежний, если ты его не подтвердил, так что чёрный экран исправится сам.
- **Каждый режим проверяется** по монитору (строчная и кадровая частота) и по переходнику
  (частота пикселей). Таблица выше показывает реальный максимум для каждого разрешения и
  то, во что он упирается.
- **Работает на популярных дистрибутивах:** Fedora, Ubuntu, Debian, Mint, Pop!_OS, Arch,
  Manjaro, openSUSE, Silverblue/Bazzite, NixOS (печатает настройки) и любой с systemd.
- **AMD, Intel и NVIDIA.** KDE, GNOME, рабочие столы на X11, Sway и Hyprland.
- **Один статический файл** без зависимостей. Интерфейс на English, Русский, Español,
  Deutsch, Français.

## Установка

Скачай готовый файл со страницы [Releases](https://github.com/ImmortallKIng/crtctl/releases/latest):

```bash
curl -fLo crtctl https://github.com/ImmortallKIng/crtctl/releases/latest/download/crtctl-linux-amd64
sudo install -m755 crtctl /usr/local/bin/crtctl
```

(Для плат на ARM — `crtctl-linux-arm64`. Контрольные суммы лежат в `SHA256SUMS`.)

Или собери сам, нужен Go 1.22 или новее:

```bash
git clone https://github.com/ImmortallKIng/crtctl
cd crtctl
make
sudo make install          # → /usr/local/bin/crtctl
```

## Быстрый старт

```bash
crtctl setup --dry-run     # показать, что будет сделано, ничего не меняя
crtctl setup               # сделать; сам попросит sudo и спросит перед каждым шагом
```

Потом можно экспериментировать:

```bash
crtctl modes               # лучшая частота для каждого разрешения
crtctl try 1000x500@75     # посмотреть любой режим; без Enter вернётся прежний
crtctl doctor              # что не так и какой командой это исправить
```

Если ЭЛТ-мониторов несколько, укажи имя выхода (`DP-2`, `HDMI-A-1`, …). Его показывает
`crtctl info`.

В [руководстве](docs/GUIDE.ru.md) всё разобрано по шагам: переходники, мастер настройки,
эксперименты, профили мониторов, NVIDIA, Secure Boot, решение проблем и что делать, если
экран погас.

## Команды

| Команда | Что делает | root |
|---|---|---|
| `setup [ВЫХОД]` | всё определить и настроить по шагам | попросит сам |
| `try [ВЫХОД] ШxВ@Гц` | сразу показать любой режим с автооткатом | нет |
| `info [ВЫХОД]` | монитор, EDID, профиль, пределы, переходник, текущий режим | необязательно |
| `doctor [ВЫХОД]` | проблемы и команда, которая исправит каждую | необязательно |
| `modes [ВЫХОД]` | максимальная безопасная частота для каждого разрешения | нет |
| `calc [ВЫХОД] ШxВ@Гц` | точные тайминги DMT / CVT / GTF и проверка по пределам | нет |
| `edid read\|show\|build` | прочитать EDID по DDC, разобрать, собрать свой | нет |
| `apply ВЫХОД ФАЙЛ` | поставить EDID до перезагрузки (`--test`) или навсегда | да |
| `reprobe ВЫХОД` | заставить драйвер перечитать EDID без перетыкания кабеля | да |
| `link show\|force\|remove` | держать канал DisplayPort на полной скорости (amdgpu) | да |
| `remove ВЫХОД` | откатить всё, что поставил crtctl | да |
| `kde list\|add\|best\|remove\|set` | свои режимы в KDE Plasma 6.6+ | нет |
| `profiles [ID]` | профили мониторов; `--new ID` создаёт свой по паспорту | нет |

Все параметры команды: `crtctl help КОМАНДА`. Язык берётся из системы; сменить можно через
`--lang en|ru|es|de|fr` или переменную `CRTCTL_LANG`.

## Где работает

| | |
|---|---|
| **Дистрибутивы** | dracut, mkinitcpio, initramfs-tools, rpm-ostree; grubby, GRUB, systemd-boot, kernelstub; запасной вариант — сервис systemd; для NixOS печатаются настройки |
| **Драйверы** | amdgpu, i915/xe, nouveau, radeon; NVIDIA с `nvidia-drm.modeset=1` (на X11 crtctl настраивает ещё и X-драйвер) |
| **Переходники** | DP→VGA (предел читается из регистров переходника), HDMI→VGA и DVI-D→VGA (165 МГц), родной VGA и DVI-I |
| **Рабочие столы для `try`** | KDE Plasma, любой на X11, Sway, Hyprland; GNOME и остальные — через временный EDID |

Полная таблица — в [руководстве](docs/GUIDE.ru.md#11-что-где-работает).

## Это безопасно?

Частоты далеко за пределами паспорта могут повредить ЭЛТ, а у некоторых старых мониторов
нет защиты. Поэтому crtctl осторожен:

- режимы вне пределов монитора и переходника отклоняются, если не добавить `--force`;
- `try` и `kde set` сами возвращают прежний режим, если не нажать Enter;
- `setup` ничего не ставит, пока ты не посмотришь на новые режимы и не ответишь «да»
  в течение 60 секунд;
- установленный EDID привязан к выходу, и crtctl предупредит, если в него воткнули другой
  монитор;
- `crtctl remove ВЫХОД` откатывает всё, а `/etc/default/grub` и записи загрузчика
  сохраняются в резервную копию перед первой правкой.

## Состояние проекта

Версия 0.3. Что проверено:

- **На живом железе:** Fedora 44, AMD RX 9070 XT (amdgpu), KDE Plasma Wayland, безымянный
  переходник DP→VGA, HP Ergo 1600.
- **Настоящими инструментами каждого дистрибутива** (в контейнерах): Ubuntu 24.04, Debian 13,
  Arch, Fedora 43 и openSUSE Tumbleweed. EDID попадает внутрь настоящего initramfs, параметры
  ядра правильные, `remove` всё убирает.
- **Пока только тестами:** NVIDIA, Intel, переходники HDMI→VGA, X11, Sway, Hyprland, GNOME,
  Silverblue, Pop!_OS, systemd-boot.

Если у тебя что-то из этого есть,
[открой issue](https://github.com/ImmortallKIng/crtctl/issues/new/choose) и приложи вывод
`crtctl doctor`, работает оно или нет. Сообщения о рабочих конфигурациях помогают не меньше,
чем об ошибках.

Не поддерживаются: чересстрочные режимы (15 кГц, аркадные мониторы, телевизоры) и фиксация
канала DP на драйверах кроме amdgpu.

## Разработка

```bash
make test        # go vet и все тесты
make release     # статические бинарники amd64 и arm64 в dist/
```

Код на чистом Go без зависимостей вне стандартной библиотеки. Пакеты в `internal/`: EDID
(`edid`), формулы таймингов (`timing`), DDC и регистры DisplayPort (`ddc`, `dpcd`), KMS
(`drm`), initramfs и загрузчики (`boot`), рабочие столы (`display`), установка (`system`),
переводы (`i18n`). Каждая строка для пользователя идёт через `i18n`, и тесты падают, если
перевода нет.

Чтобы выпустить релиз, поменяй `version` в `main.go` и запушь такой же тег (`v0.3.0`).
GitHub Actions соберёт бинарники и приложит их к релизу.
